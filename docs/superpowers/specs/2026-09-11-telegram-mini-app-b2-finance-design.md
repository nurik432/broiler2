# Telegram Mini App — B2: финансы и ресурсы (расходы, продажи, зарплаты, долги, корм, уголь)

Дата: 2026-09-11

## Проблема

После Фундамента и B1 в мобильном приложении реализованы навигация, авторизация, ежедневный цикл (журнал партии, отчёт, цеха, задачи). Раздел финансового и ресурсного учёта — расходы, продажи, зарплаты/сотрудники, долги цеха, корм, уголь — на маршрутах `/expenses`, `/sales`, `/salaries`, `/debts`, `/feed`, `/coal` до сих пор показывает `<MobileStub>`. Это подпроект B2 по роадмапу Фундамента.

## Цель

Реализовать 6 мобильных разделов с полным функциональным паритетом десктопных `ExpensesPage`, `SalesPage`, `SalariesPage` (три вкладки: `CreateEmployeeTab`, `HireFireTab`, `SalaryTab`), `DebtsPage`/`DebtTab`, `FeedPage`, `CoalPage`, на примитивах Фундамента/B1, заменив `<MobileStub>` на всех шести маршрутах.

## Вне рамок

- **B3** (лекарства, заметки) и **C** (3 админских экрана) — отдельные подпроекты.
- Изменение логики RPC (`get_expenses`, `get_sales_with_stats`, `get_feed_deliveries`, и т.д.), схемы БД, `utils/calculateSalary.js` — переиспользуются как есть.
- Исправление существующих десктопных страниц.
- Новые функции сверх десктопного паритета.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Массовое выделение расходов + групповая привязка к партии (десктопный липкий бар с чекбоксами) | Не переносим 1:1 — каждая карточка расхода получает собственное действие «Привязать к партии» через `BottomSheet` |
| HireFireTab: объединение дублей физлиц, ручное добавление исторического периода, редактор ступенчатых тарифов | Полный паритет — переносятся все три операции |
| Автокомплит имени (клиент в продажах, физлицо в зарплатах) | Один общий компонент `NamePicker` (генерализация десктопного `PersonAutocomplete`, который уже параметризован списком `{id, full_name}`) — используется и для `customers`, и для `persons` |
| Автокомплит кредитора в долгах | Не отдельный компонент — обычный `<input list="...">` (datalist), как на десктопе; Telegram WebView (Chromium) рендерит нативный список подсказок |
| Дашборды (Корм/Уголь/Долги) | Новый общий компонент `StatGrid` — сетка карточек-метрик вместо десктопного `grid-cols-4/5` |

`TelegramApp.jsx`: 6 маршрутов-стабов меняются на реальные компоненты.

Переиспользуется без изменений: `src/utils/calculateSalary.js` (`calculateSalary(employee, batch)`), все существующие RPC/таблицы, Foundation/B1-примитивы (`Card`, `ListRow`, `SectionHeader`, `StatusPill`, `EmptyState`, `Spinner`, `BottomSheet`, `ConfirmSheet`, `FormField`, `NumberStepper`, `SegmentedControl`, `Tabs`), Telegram-хуки.

## Расходы (`MobileExpensesPage`)

### Данные

`supabase.rpc('get_expenses')` → строки `{id, user_id, expense_date, description, amount, category, batch_id, created_at, expense_scope, batch_name, batch_is_active}`; активные батчи (`broiler_batches` где `is_active=true` и не сводная).

### Поведение

- `SegmentedControl` Рабочие/Домашние — фильтр по `expense_scope` (`work`/`personal`).
- Переключатель «Показать расходы архивных партий» — без него видны только записи без `batch_id` или с `batch_is_active === true`.
- Сворачиваемый отчёт за период (даты с/по, по умолчанию текущий месяц) — сумма отфильтрованных расходов за диапазон, считается на клиенте.
- Форма добавления: дата, описание, сумма, категория (текст), привязка к партии (опционально) — `insert` в `expenses` с `expense_scope: activeTab`, `user_id`.
- Список — карточки (дата/время, описание, категория, бейдж партии, сумма), кнопки «Изменить» (`BottomSheet` с теми же полями + привязкой к партии) и «Удалить» (`ConfirmSheet`).

## Продажи (`MobileSalesPage`)

### Данные

`supabase.rpc('get_sales_with_stats')` → `{id, sale_date, customer_id, customer_name, weight_kg, price_per_kg, created_at, batch_id, batch_name, batch_is_active, total_amount, total_paid, balance}`; `customers` (`id, full_name`, свои через RLS); активные батчи.

### Поведение

- Переключатель архивных партий — как в расходах.
- Сворачиваемый отчёт за период: сумма продаж / сумма платежей / остаток за диапазон дат.
- Форма добавления: дата, клиент (`NamePicker` — «без клиента» допустимо, кнопка создать нового прямо тут же), вес (кг), цена/кг, партия (опционально) — `insert` в `sales`.
- Список — карточки (дата, клиент, вес×цена, сумма, оплачено, статус «Выплачено»/«Остаток: N»), тап по карточке (не по кнопкам) → `BottomSheet` «История платежей по продаже»: суммы (к оплате/оплачено/остаток) + список платежей (дата, сумма, удалить).
- Кнопка «+ Новое поступление» → отдельный `BottomSheet`: клиент (`NamePicker`, обязателен), сумма, дата → на подтверждение: свежий `get_sales_with_stats`, отфильтровать неоплаченные продажи этого клиента (`balance > 0`), отсортировать по дате возрастания, проверить `сумма ≤ сумма всех остатков` (иначе ошибка), распределить сумму по продажам от старой к новой (`insert` несколько строк в `payments`).
- «Изменить»/«Удалить» на карточке продажи — те же поля, что форма добавления; удаление — `ConfirmSheet` с текстом про платежи.

## Зарплаты (`MobileSalariesPage` + 3 вкладки)

### Общие данные (грузятся один раз, передаются во все вкладки)

`persons` — `select *, employees(*, broiler_batches(id, batch_name, is_active, batch_end))`, у каждого person `employees` отсортированы по `start_date` убыв. (нулевой элемент — текущий/последний период). `activeBatches` — все батчи (не только активные) для полей формы.

### Вкладка «Создание сотрудника»

`NamePicker` по `persons`: выбор существующего (добавит новый период — с предпроверкой на уже открытый период, ошибка `23505` от уникального индекса как финальная защита) или создание нового физлица (`insert` в `persons`, затем `employees`). Поля: должность, дата начала, партия (опционально).

### Вкладка «Приём и увольнение»

- Список сотрудников карточками (фильтр «уволенные» скрыт по умолчанию — показываются только с открытым периодом на активной партии).
- Тап по карточке → детальная панель с действиями через `BottomSheet`:
  - **Уволить** (`ConfirmSheet`) — `end_date = сегодня, is_active = false`.
  - **Принять заново** (если уволен) — новый `employees`-период, ставка/тарифы подтягиваются из последнего периода.
  - **Редактировать текущий период** — ФИО (`persons.full_name` + `employees.full_name`), должность, даты начала/окончания, партия, ставка/день, дни отсутствия, редактор ступеней (`salary_tiers: [{days, rate}]` — добавить/удалить строку).
  - **Добавить период** — тот же набор полей что редактирование, но создаёт новую запись `employees` (для исторических периодов задним числом).
  - **Объединить с другим физлицом** — `NamePicker` поиска дубля (исключая текущего), подтверждение переносит все `employees`-записи дубля на текущего `person_id` и удаляет дубль-`person` (guard: у обоих не может быть открытый период одновременно).
  - **Удалить** — `ConfirmSheet`, каскадно удаляет периоды и зарплаты.
- История периодов — список карточек (должность, даты, ставка, партия).

### Вкладка «Начисление зарплаты»

- Выбор сотрудника (`NamePicker` или простой `select`, если список короткий).
- Виджет начисления за текущий период: `calculateSalary(recentEmployment, batch)` (переиспользуется без изменений) → отработанные дни, начислено, детализация по ступеням.
- Итоги текущего периода: авансы/зарплата/по партиям.
- Форма выплаты: дата, сумма, тип (аванс/зарплата) — `insert` в `salaries`.
- Таблица выплат текущего периода (карточки) — редактирование (дата/сумма/тип) и удаление.
- Сворачиваемый блок «Выплаты прошлых периодов» — сгруппировано по прошлым `employees`-записям, каждая со своим начислено/выплачено и таблицей.

## Долги цеха (`MobileDebtsPage`)

### Данные

`debts` — `select *, debt_payments(*)`, `order by debt_date desc`. Поля `debts`: `id, amount, description, debt_date, is_settled, user_id, creditor_name`.

### Поведение

- `StatGrid`-дашборд: всего долгов / оплачено / остаток / активных-закрытых, плюс разбивка по кредиторам (карточка на каждого: долг/оплачено/остаток).
- Форма записи долга: кредитор (текст + `datalist` подсказок из уже известных имён), сумма, дата, «за что» (опционально).
- Фильтры: по кредитору (select), «показать закрытые» (переключатель).
- Список — карточки с прогресс-баром оплаты, тап → раскрытие: история погашений (дата/сумма/удалить) + форма частичной оплаты (если не закрыт: сумма/дата/комментарий — `insert` в `debt_payments`; если сумма покрывает остаток — авто-`is_settled=true`) + кнопки «Отметить закрытым/вернуть в активные» и «Удалить долг».

## Корм (`MobileFeedPage`)

### Данные

`supabase.rpc('get_feed_deliveries')` → `{id, user_id, delivery_date, feed_type, quantity_kg, created_at, batch_id, batch_name, batch_is_active, price_per_kg, amount, transaction_type, company}`.

### Поведение

- `StatGrid`-сводка: старт/рост/финиш (мешки + кг + сумма, если есть цена) + итого.
- Переключатель архивных партий.
- Форма прихода: дата, тип корма (старт/рост/финиш), мешки (1 меш. = 40 кг, авто-расчёт кг), партия (опционально), цена/кг (опционально), тип оплаты (сразу/в долг, только если указана цена), фирма (опционально).
- Список — карточки (дата, тип, мешки+кг, сумма, партия), изменить/удалить.

## Уголь (`MobileCoalPage`)

### Данные

`coal_transactions` — `select *`, `order by transaction_date desc, created_at desc`. Поля: `id, transaction_date, transaction_type ('purchase'|'debt'|'payment'), quantity_kg, price_per_kg, amount, description, is_hidden`.

### Поведение

- `StatGrid`-дашборд: всего кг, куплено, взято в долг, оплачено, остаток долга (считается из видимых, не скрытых записей).
- `Tabs` Покупка/В долг/Оплата, каждая своя форма (покупка/долг: дата, кол-во кг, цена/кг, описание, партия — авто-расчёт суммы; оплата: дата, сумма, описание).
- Переключатель «Показать скрытые».
- История операций — карточки (дата, тип-бейдж, описание, кол-во/цена, сумма со знаком +/−), кнопки скрыть/показать и удалить.
